## 2. Content Loss Detection (The "Duplicate" Discard Bug)

The previous agent used a script (`generate_kb.py`) that matched PDF documents to the 80 topics based on numbers found in the text or filename. 

**The Critical Bug:** When multiple source files mapped to the same topic, the agent **silently discarded all but the longest file**. 

### Mapped KB Topics with Discarded Files:
- **Topic 01 (Introduction):** Mapped to 27 different PDFs. The agent kept 1 and **discarded 26 files**.
- **Topic 03 (Sign Up):** Mapped to 5 files. **Discarded 4 files.**
- **Topic 06 (Email Verification):** Mapped to 3 files. **Discarded 2 files.**
- **Topic 07 (Identity Verification):** Mapped to 3 files. **Discarded 2 files.**
- **Topic 21 (Follow System):** Mapped to 2 files. **Discarded 1 file.**

Because of this bug, **entire WiseIN features, restrictions, and policies are completely missing** from the `knowledge_base/` and were never embedded into Qdrant. If two documents contained different/overlapping information for the same topic, the agent chose one and deleted the other, rather than merging them or preserving the conflict.

## 3. PDF Extraction Quality (Structural Corruption)

The original source PDFs were extracted using `pypdf`, but the text extraction suffered from severe formatting artifacts.

1. **The "Vertical List of Words" Problem:** In many PDFs, `pypdf` extracted text with frequent newlines (often every single word on its own line).
2. **The Markdown Destruction:** The `generate_kb.py` script then took this raw text and replaced every single newline with a **double newline** (`\n\n`), completely destroying the paragraph structure.
3. **Chunking Failure:** Because Markdown treats double newlines as paragraph breaks, the chunking script (`chunk_documents.py`) treated every single word/fragment as a separate paragraph, grouping them into blobs of 1500 characters.

### Impact on the AI Assistant:
- **Tables:** 100% destroyed. Columns and rows were flattened into an unreadable vertical list of words. The AI will not be able to read limits, pricing, or comparative features.
- **Bullet Points & Steps:** Destroyed. Ordered steps (1, 2, 3) are disconnected from their instructions.
- **Headings:** Lost context.
- **Sentences:** Broken mid-sentence across chunks.

## 4. Conflict Detection

Due to the silent discarding of files (see Section 2), conflicting information was unilaterally "resolved" by deleting the smaller documents. We cannot currently map all conflicts because the data was deleted before it reached the markdown stage. 

*Example:* `WISEIN WAVES DOCUMENTATION018.pdf` and `_WISEIN WAVES DOCUMENTATION018.pdf` were both found, but one was discarded. If they contained conflicting info about the Waves feature, that conflict is lost.

## 5. Next Steps / Actions Recommended BEFORE Phase 7

If we proceed to Phase 7 (LLM Answer Generation) with the current Qdrant database, the AI will confidently hallucinate or fail to answer basic questions because its underlying knowledge is corrupted, missing, and unreadable.

**Do NOT implement Phase 7 yet.**

### Required Remediation Plan:
1. **Rewrite `generate_kb.py` (Phase 1):**
   - Fix the regex mapping to correctly identify topic mapping without false positives.
   - Stop discarding files! If multiple PDFs map to a topic, append their contents together and insert a warning header indicating a potential conflict/overlap.
   - Replace `pypdf` with a more robust parser (like `pdfplumber` or `pymupdf` if available) OR fix the newline logic so that sentences and paragraphs are joined correctly.
   - Detect tables in the PDFs and convert them to Markdown tables.
2. **Regenerate the Knowledge Base (Phase 2):** Run the new extraction to create 80 healthy Markdown files.
3. **Regenerate Chunks (Phase 3):** Run `chunk_documents.py` (it will work correctly once the markdown is healthy).
4. **Regenerate Embeddings & Qdrant (Phase 4 & 5):** Re-embed the new chunks and push them to Qdrant (overwriting the existing corrupted 2,082 vectors).

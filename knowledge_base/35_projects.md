1. PROJECTS — OVERVIEW 
The Projects section is a component of the WiseIN individual profile where users can 
showcase projects they have worked on. 
Projects provide additional context about a person's practical work, technical experience, 
professional interests, and areas of expertise. 
WiseIN's current Privacy Policy explicitly identifies projects as profile information that 
users may choose to add to their profile, alongside information such as professional bio, 
skills, experience, education, and social links.  
The Projects section is therefore part of the user's broader professional profile. 
 
2. PURPOSE OF THE PROJECTS SECTION 
The Projects section allows users to present practical work they have completed, 
contributed to, or worked on. 
Projects can help communicate:

Professional interests  
•

• 
Academic work  
•

The Projects section should therefore be understood as structured profile information, 
rather than the same thing as a social-media Post or Clip.

The exact appearance and available actions may change as the WiseIN application

4. ADDING A PROJECT 
A user can add a project through the Projects section of their profile. 
General flow: 
1. Open the WiseIN individual profile.  
2. Locate the Projects section.  
3. Select “+ Add Projects.”  
4. Complete the fields displayed by the current project form.  
5. Submit/save the project.  
6. The project appears in the user's profile if the operation succeeds.  
The exact project form fields should always be taken from the current WiseIN application.

6. PROJECTS FOR STUDENTS 

The Projects section can be particularly useful for students and fresh graduates because 
projects can provide practical context alongside their Education and Skills. 
For example, a student profile could contain: 
Education 
B.Tech / undergraduate education 
Skills 
Python, JavaScript, SQL, etc. 
Projects 
AI application, full-stack application, academic project, etc. 
This allows the profile to communicate both academic background and practical work. 
WiseIN's current Student offering is designed for students and fresh graduates and 
includes access to career-related opportunities such as the internship and job board.  
However: 
Adding a Project does not automatically make a user Student-verified. 
Projects, Education, and Student Verification are separate profile/product concepts.

A project may be related to a user's education, but the information belongs in the Projects

8. PROJECTS VS EXPERIENCE 
Projects and professional experience should not be treated as identical. 
Experience 
Describes professional employment or work history. 
Projects 
Describe specific work or things the user has built, developed, researched, or contributed 
to. 
For example: 
“Software Engineer Intern at Company X” 
belongs to the Experience/Employment context. 
“Developed an AI-powered resume analysis platform” 
can be presented as a Project. 
A project can be associated with professional experience, education, or personal work 
depending on the user's circumstances. 
 
9. PROJECTS VS POSTS 
A Project is structured profile information. 
A Post is content shared with the WiseIN community/feed. 

For example: 
“My AI Resume Analyzer” 
could be added as a Project to showcase it on the user's profile. 
The user could separately create a Post discussing: 
“How I built my AI Resume Analyzer.” 
The two are not the same feature. 
WiseIN's current website describes posts/content as part of the platform's 
social/professional networking experience, while projects are identified separately as 
profile information.  
 
10. PROJECTS VS CLIPS 
A Project is a profile entry. 
A Clip is a video-oriented content format. 
For example: 
A user can list an application they developed under Projects. 
They may separately publish a Clip demonstrating that application, provided the relevant 
account/content capabilities are available. 
Do not tell users that adding a Project automatically creates a Clip. 
Do not tell users that every Project must have a Clip. 
 
11. PROJECTS VS WEBSITE / PORTFOLIO 
The profile can also contain professional website or portfolio information. 
These features serve different purposes. 
Projects 
Show individual pieces of work. 
Website / Portfolio 
Provides an external destination where users can showcase broader work. 

A user may use both. 
For example: 
Project → “AI Resume Analyzer” 
Portfolio → personal website containing multiple projects. 
The chatbot should not require a portfolio URL when adding a project unless the current 
Project form explicitly requires it. 
 
12. EDITING A PROJECT 
If a user wants to modify an existing project: 
1. Open their WiseIN profile.  
2. Locate the Projects section.  
3. Find the relevant project.  
4. Open the available action menu.  
5. Select the edit option if available.  
6. Update the information.  
7. Save the changes.  
The current profile interface previously provided shows action controls associated with 
project entries. 
The exact menu labels should follow the current application. 
 
13. DELETING A PROJECT 
If the current project action menu provides a delete/remove option, the user can use it to 
remove the project. 
General flow: 
1. Open the profile.  
2. Go to Projects.  
3. Locate the project.  

4. Open its action menu.  
5. Select the available delete/remove option.  
6. Confirm if WiseIN requests confirmation.  
Do not promise deletion behavior that is not supported by the current application. 
WiseIN's Privacy Policy states that users can edit or delete certain information through 
their account settings, subject to applicable restrictions.

16. PROJECT VISIBILITY 
Projects are profile information. 
WiseIN's Privacy Policy explains that users can provide profile information including 
projects and that certain profile information may be visible to other users depending on 
privacy settings.  
Therefore, the chatbot should explain visibility carefully. 
Safe response 
“Projects are part of your WiseIN profile. Their visibility depends on the profile and privacy 
controls available on your account.” 
Do not claim: 
“Everyone can always see your projects.” 
or: 
“Only your connections can see your projects.” 
unless the current application explicitly establishes that behavior.

19. PROJECTS AND COPYRIGHT 
Users should only publish project material they have the right to share. 
If a project belongs to an employer, client, university, or another organization, the user 
should make sure they have permission to publicly describe or showcase it. 
WiseIN's Content Policies prohibit copyright infringement and unauthorized use of other 
people's content.  
The chatbot should therefore not encourage users to upload or publish proprietary material 
simply because they worked on the project. 
 
20. PROJECTS AND CREDENTIAL CLAIMS 
Users should accurately represent their contribution to a project. 
For example, a user should not claim: 
“I built the entire platform” 
if they only contributed to one component. 
WiseIN's Content Policies prohibit impersonation, fake expertise, and fake credentials.  
The chatbot can recommend accurate descriptions such as: 
“Contributed to the backend API development.” 
or: 
“Worked on the machine-learning component.” 
when that reflects the user's actual contribution. 
 
21. PROJECTS AND PROFESSIONAL CREDIBILITY 
Projects can help users demonstrate practical work and professional interests. 
WiseIN's overall platform positioning emphasizes verified professional identities and 
discovering relevant people based on skills, industry, and experience.  
Projects can therefore provide additional context when someone views a profile. 
However, the chatbot should not claim that adding projects guarantees: 

• 
More profile views  
• 
More connections  
• 
Better search ranking  
• 
More job opportunities  
• 
Recruiter responses  
•

unless such behavior is explicitly documented by WiseIN.

30. PROJECT NOT SAVING 
If a user says: 
“My project is not saving.” 
Use this troubleshooting sequence. 
Step 1 — Check the form 
Ask the user to review the fields currently shown by the Project form. 
Step 2 — Check validation 
Look for: 
• 
Required-field errors  
• 
Invalid input  
• 
Unsupported characters  
• 
URL validation errors, if a URL field exists  
• 
Other messages displayed by the application  
Do not invent specific validation rules. 
Step 3 — Retry 
Ask the user to save again. 
Step 4 — Refresh 
If appropriate: 
• 
Refresh the profile.  
• 
Reopen the profile.  
• 
Check whether the project was actually saved.  
Step 5 — Browser/app troubleshooting 

If the issue continues: 
• 
Check the internet connection.  
• 
Refresh the application.  
• 
Sign out and sign back in.  
• 
Try a current supported browser.  
• 
Try the mobile application if the feature is available there.  
Step 6 — Escalate 
If the project still cannot be saved, direct the user to WiseIN support. 
The current WiseIN Contact page provides a contact form and states that the team replies 
within 24 hours.  
 
31. PROJECT NOT VISIBLE 
If the user says: 
“I added a project but I can't see it.” 
The chatbot should check: 
1. Whether the save operation completed.  
2. Whether the user is viewing the correct profile.  
3. Whether refreshing/reopening the profile makes the entry appear.  
4. Whether the project is visible in the profile editing interface.  
5. Whether a privacy or visibility setting affects the display.  
The chatbot should not assume that the project was deleted.

• 
The user is viewing a different account/profile.  
• 
A visibility setting changed.  
• 
The application failed to load the profile information.

43. COMMON PROJECT QUESTIONS 
“Where can I add a project?” 
Open your WiseIN profile and locate the Projects section. Select “+ Add Projects.” 
“Can I add multiple projects?” 
If the current WiseIN interface allows multiple project entries, you can add your projects 
separately. WiseIN does not currently provide a public maximum that should be stated by 
the chatbot. 
“Can I edit a project?” 
Use the available action menu on the project entry and select the edit option if it is 
available. 
“Can I delete a project?” 

Use the available project action menu and select the delete/remove option if provided by 
the current interface. 
“Does WiseIN verify my project?” 
Do not assume so. A project entry is profile information and is not automatically an 
independently verified credential. 
“Can I add a college project?” 
Yes. A project can be used to showcase relevant practical or academic work, subject to the 
current Project form. 
“Can I add a GitHub project?” 
If the current Project form provides a suitable field or link option, a user can provide the 
relevant public project link. The chatbot should not claim that GitHub integration is built in 
unless confirmed. 
“Can recruiters see my projects?” 
Projects are profile information. Visibility depends on the applicable WiseIN profile/privacy 
controls. 
“Why is my project not showing?” 
Check that the project was successfully saved, refresh/reopen the profile, and verify that it 
is present in the profile editing view. If it remains missing, contact support.

52. GOLDEN ANSWER — WHAT IS PROJECTS? 
If the user asks: 
“What is Projects on WiseIN?” 
Use: 
Projects is a section of your WiseIN profile where you can showcase practical work 
you've completed, contributed to, or worked on. It is separate from Education, 
Experience, Posts, and Clips and is intended to provide additional context about your 
professional or practical work. 
 
53. GOLDEN ANSWER — HOW TO ADD A PROJECT 
To add a project, open your WiseIN profile and go to the Projects section. Select “+ Add 
Projects” and complete the information shown in the current Project form. Save the entry 
when you're finished. 
 
54. GOLDEN ANSWER — PROJECT VERIFICATION 
If the user asks: 
“Are projects verified on WiseIN?” 
Use: 
A project listed on your profile should not automatically be treated as a verified 
credential. WiseIN's verified-profile system verifies the applicable user identity, while 
Projects are profile information that users can add. Unless your profile or the application 
explicitly shows a project-specific verification status, don't assume the project has been 
independently verified. 
WiseIN's website describes its identity-verification system separately from profile 
information such as projects.  
 
55. GOLDEN ANSWER — PROJECT VS EDUCATION 

Education describes your academic background, while Projects showcase practical work 
you have completed or contributed to. For example, your degree belongs in Education, 
while an application you built can be listed under Projects. 
 
56. GOLDEN ANSWER — PROJECT VS POST 
A Project is part of your profile and showcases your work. A Post is content you publish to 
the WiseIN community/feed. You can use both: list the project on your profile and create a 
Post to discuss or share it. 
 
57. GOLDEN ANSWER — PROJECT NOT SAVING 
If your project isn't saving, first check the fields and validation messages shown by the 
current Project form and try saving again. Refresh and reopen your profile to confirm

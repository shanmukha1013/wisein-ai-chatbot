69. Human Escalation 
✦ HUMAN ESCALATION 
Get help from a real person 
WiseIN is designed to resolve common user questions through its support system and 
AI-powered customer support. When an issue cannot be resolved automatically, requires 
account-specific assistance, or needs human intervention, the user can be escalated to the 
WiseIN support team. 
Human escalation ensures that users can always reach a real support representative when 
automated assistance is not sufficient. 
 
69.1 When Human Escalation Is Required 
The support system should escalate a conversation when: 
●​ The AI cannot confidently answer the user's question. 
●​ The user's issue requires access to account-specific information. 
●​ The issue involves a technical bug that cannot be resolved through normal 
troubleshooting. 
●​ The user reports a payment or subscription-related problem. 
●​ The user reports an account, login, OTP, or verification issue that requires backend 
investigation. 
●​ The user reports a privacy or security concern. 
●​ The user wants to report serious abuse, harassment, scams, impersonation, or other 
policy violations. 
●​ The user has already attempted the suggested troubleshooting steps without success. 
●​ The user explicitly requests to speak with a human support representative. 
●​ The issue requires action that the AI assistant is not authorized to perform. 
●​ The conversation involves a sensitive or potentially serious issue requiring manual 
review. 
 
69.2 AI-to-Human Escalation Flow 

The expected support flow is: 
User asks a question → AI analyzes the issue → AI provides an answer → User confirms 
whether the issue is resolved 
If the issue is not resolved: 
AI attempts additional troubleshooting → Issue remains unresolved → Human escalation 
is offered → User submits/escalates the issue → Support team reviews it → Human 
representative responds 
Basic flow 
1.​ User starts a conversation 
○​ User describes their problem or question. 
2.​ AI identifies the issue 
○​ The AI determines the relevant WiseIN feature, workflow, or problem category. 
3.​ AI provides assistance 
○​ The AI gives instructions based on the WiseIN knowledge base. 
4.​ User indicates the issue is unresolved 
○​ The user can request additional help or human assistance. 
5.​ AI checks whether escalation is necessary 
○​ If the issue requires human intervention, escalation is initiated. 
6.​ Issue is transferred to support 
○​ The relevant conversation and available context should be provided to the 
support team. 
7.​ Human support reviews the issue 
○​ A support representative investigates the problem. 
8.​ Human representative responds 
○​ The user receives a direct response or resolution. 
 
69.3 User Requesting a Human 
Users should be able to explicitly request human assistance. 
Examples: 
●​ "I want to talk to a human." 
●​ "Can someone from support help me?" 
●​ "I still have this problem." 
●​ "This didn't solve my issue." 
●​ "Connect me with customer support." 
●​ "I need someone from WiseIN to look into this." 

The AI should not repeatedly provide the same automated instructions when the user has 
clearly requested human assistance. 
 
69.4 Information Passed During Escalation 
When an issue is escalated, the support team should receive relevant information available from 
the conversation. 
This may include: 
●​ User's name 
●​ Registered email address 
●​ User/account identifier where applicable 
●​ Conversation history 
●​ User's original question 
●​ AI responses already provided 
●​ Troubleshooting steps already attempted 
●​ Reported error message 
●​ Relevant feature or module 
●​ Date/time of the issue 
●​ Screenshots or other evidence provided by the user 
●​ Relevant report category 
●​ Current escalation status 
The purpose is to prevent the user from having to explain the same problem repeatedly. 
 
69.5 Conversation History 
The chatbot should maintain the conversation history required to understand the user's issue. 
For example: 
User: "I can't log in." 
AI: "Are you receiving an OTP?" 
User: "No." 
AI: "Have you checked your email or phone number?" 
User: "Yes, but I still haven't received it." 

If this conversation is escalated, the human support representative should be able to 
understand that the user has already attempted the suggested steps.

69.7 AI Responsibilities Before Escalation 
Before escalating a normal support issue, the AI should: 
1.​ Understand the user's problem. 
2.​ Identify the relevant WiseIN feature. 
3.​ Search the approved knowledge base. 
4.​ Provide clear instructions. 
5.​ Ask relevant follow-up questions if required. 
6.​ Avoid making unsupported claims. 
7.​ Check whether the suggested solution resolved the problem. 
8.​ Escalate when the issue cannot be resolved confidently. 
The AI should not pretend that an issue has been fixed when it has not been resolved. 

 
69.8 When AI Should Not Continue Troubleshooting 
The AI should avoid endless troubleshooting. 
Human escalation should be considered when: 
●​ The same problem continues after reasonable troubleshooting. 
●​ The user has already completed the documented steps. 
●​ The issue appears to be caused by a backend/system problem. 
●​ The AI does not have enough information to provide a reliable answer. 
●​ The required action can only be performed by WiseIN staff. 
●​ The issue involves sensitive account information. 
●​ The user specifically requests human support. 
 
69.9 Human Support Response 
After escalation, the support representative should: 
●​ Review the conversation. 
●​ Understand the reported problem. 
●​ Check relevant account or system information where authorized. 
●​ Investigate the issue. 
●​ Provide clear instructions or resolution. 
●​ Request additional information if necessary. 
●​ Inform the user if further investigation is required. 
●​ Follow up when appropriate. 
The response should be specific to the user's issue rather than simply repeating generic 
troubleshooting instructions. 
 
69.10 Support Response Time 
WiseIN's customer-support page states that users should receive a response within 24 hours, 
usually faster. 
The stated support flow is: 

1. User sends the message​
 Takes less than 10 seconds. 
2. WiseIN team reads it​
 Within a few hours. 
3. User receives a reply​
 Within 24 hours. 
4. Human response​
 The support page states that a real human responds rather than a template or bot. 
 
69.11 Escalation Status 
An escalation system can maintain statuses such as: 
●​ Open – Issue has been submitted. 
●​ Under Review – Support team is investigating. 
●​ Waiting for User – Additional information is required. 
●​ In Progress – Support is working on the issue. 
●​ Resolved – The issue has been addressed. 
●​ Closed – The support conversation has been completed. 
 
69.12 Evidence and Attachments 
Users may need to provide evidence to help support investigate an issue. 
Examples include: 
●​ Screenshots 
●​ Error messages 
●​ Screen recordings 
●​ Relevant documents 
●​ Transaction/payment evidence where applicable 
For content reports, WiseIN's reporting interface allows users to upload up to 3 images, with a 
maximum of 5 MB per image. 
Sensitive information should only be submitted when necessary and through the appropriate 
WiseIN support/reporting mechanism. 

 
69.13 Human Escalation for Content Reports 
Content-related issues can also require human review. 
Users can report issues such as: 
●​ Harassment 
●​ Spam 
●​ Inappropriate content 
●​ Scam/Fraud 
●​ Impersonation 
●​ Violence 
●​ Other violations 
The reporting workflow includes: 
Report User → Select Reason → Provide Details → Optional Evidence → Submit Report 
→ Human/Moderation Review 
This is particularly important when automated assistance cannot determine the appropriate 
action. 
 
69.14 Escalation for Serious Issues 
Issues involving serious safety, privacy, security, fraud, threats, impersonation, or other 
significant policy violations should be routed for appropriate human review. 
The AI should avoid making final enforcement decisions unless the system explicitly authorizes 
it to do so. 
The human support/moderation team can investigate the available information and take the 
appropriate action under WiseIN's applicable policies. 
 
69.15 Privacy During Human Escalation 
Only information necessary to resolve the user's issue should be shared with the support team. 
The support process should respect WiseIN's privacy requirements. 

Users should not be asked to unnecessarily provide: 
●​ Passwords 
●​ OTPs 
●​ Authentication codes 
●​ Unnecessary financial information 
●​ Sensitive personal information unrelated to the issue 
 
69.16 AI Handoff Message 
A suitable chatbot message when escalation is required: 
I couldn't resolve this issue with the information available to me. I can 
connect you with WiseIN's support team so they can look into it. Would you 
like me to escalate this conversation? 
If the user agrees: 
Your issue has been escalated to the WiseIN support team. We've included 
the conversation details so you won't need to explain everything again. A 
support representative will review it and get back to you. 
 
69.17 If the User Does Not Want Escalation 
If the user declines human support, the AI can continue providing relevant self-service 
assistance. 
Example: 
No problem. I can continue helping you here. Tell me what part of the issue 
you'd like to try again. 
 
69.18 Knowledge-Base Requirement 
For the WiseIN AI customer-support chatbot, human escalation should be treated as a fallback 
mechanism, not a replacement for the knowledge base. 

The chatbot should first use the documented WiseIN knowledge base to answer questions 
about: 
●​ Login 
●​ Home 
●​ Explore 
●​ Waves 
●​ Jobs 
●​ My Network 
●​ Chat 
●​ Meetings 
●​ Analytics 
●​ Organizations 
●​ Profile 
●​ Posts 
●​ Events 
●​ Subscriptions 
●​ Verification 
●​ Settings 
●​ Privacy 
●​ Security 
●​ Account management 
●​ Reporting 
●​ Content policies 
●​ Community guidelines 
When the documented information is insufficient, the system should escalate instead of 
inventing an answer. 
 
69.19 Recommended Escalation Architecture 
For the WiseIN AI customer-support system: 
User → AI Chatbot → Knowledge Base/RAG → Answer 
If resolved: 
→ Conversation Ends 
If unresolved: 
→ Collect Issue Details → Create Support Ticket → Human Support → Resolution → User 

This creates a clear separation between: 
AI: First-level assistance and troubleshooting​
 Human Support: Account-specific investigation, complex issues, exceptions, and final 
resolution 
 
69.20 Key Principle 
AI should solve what it knows. Human support should handle what requires 
human judgment, investigation, or intervention.

1. EMPLOYMENT — OVERVIEW 
The Employment section is a component of a user's WiseIN professional profile used to 
present their professional work experience. 
It helps a user represent their career background by recording information related to: 
• 
Work experience  
• 
Professional roles  
• 
Organizations  
• 
Career achievements  
The existing WiseIN application documentation specifically identifies Employment as the 
profile area for recording work experience, roles, organizations, and relevant career 
information.  
WiseIN's broader profile structure also treats Employment as the user's experience 
category, separate from Education and Projects.  
The WiseIN Privacy Policy also confirms that users may voluntarily add professional profile 
information such as experience, education, projects, skills, professional bio, and social 
links.  
 
2. PURPOSE OF THE EMPLOYMENT SECTION 
The Employment section is intended to help users: 
• 
Present their professional background.  
• 
Show previous and current work experience.  
• 
Display professional roles.  

• 
Associate work experience with organizations.  
• 
Communicate career progression.  
• 
Highlight relevant career achievements.  
• 
Give other users additional context about their professional identity.  
• 
Strengthen the user's professional profile when networking or discovering 
opportunities.  
Employment is therefore different from: 
About 
Used for the user's professional introduction, description, background, interests, and 
summary. 
Key Skills 
Used to highlight professional capabilities and skills. 
Education 
Used for academic background and learning-related information. 
Projects 
Used to showcase projects and practical work. 
Employment 
Used specifically for professional work experience, roles, organizations, and career 
information. 
The existing WiseIN documentation explicitly separates these profile categories.

4. HOW TO ADD EMPLOYMENT 
The verified general workflow is: 
1. Open the user's WiseIN Profile.  
2. Navigate to the Employment section.  
3. Select Add employment.  
4. Enter the required employment information.  
5. Complete the available form fields.  
6. Save the employment record using the available save/submit action.  

The existing WiseIN product documentation explicitly provides the workflow: 
Open your profile and go to the Employment section. Select Add employment and enter the 
required information. 
The profile interface provides an Add employment action when employment information 
has not yet been added or when the user wants to add another employment record.  
 
5. ADDING MULTIPLE EMPLOYMENT RECORDS 
The Employment section is not limited to a single work experience entry. 
The existing documentation states that the Add employment action is available when a 
user wants to add another employment record.  
Therefore, a user can maintain multiple employment records representing different stages 
of their professional background. 
Examples may include: 
• 
Current employment  
• 
Previous employment  
• 
Internship experience  
• 
Professional roles at different organizations  
• 
Multiple career positions  
However, the AI must not claim that a particular employment type is officially 
supported unless that option is confirmed in the current application. 
 
6. EMPLOYMENT INFORMATION — VERIFIED SCOPE 
The currently verified WiseIN documentation establishes that Employment covers: 
Work Experience 
Information describing the user's professional work background. 
Role 
The professional position or function performed by the user. 

Organization 
The company, institution, startup, organization, or other professional entity associated with 
the employment. 
Career Achievements 
Relevant accomplishments associated with the user's professional experience. 
These four concepts are explicitly identified in the current WiseIN product documentation.

59. CHATBOT ANSWER RULES 
Rule 1 — Do not invent Employment fields 
If the exact current fields are unknown, say so. 
Rule 2 — Do not invent validation rules 
Never invent character limits, date requirements, record limits, or mandatory fields. 
Rule 3 — Do not invent privacy behavior 

Never assume Employment is public/private or has a dedicated visibility switch. 
Rule 4 — Do not invent verification 
Employment records must not be described as independently verified unless WiseIN 
confirms employment verification. 
Rule 5 — Do not invent deletion behavior 
Only describe a Delete/Remove workflow when verified. 
Rule 6 — Do not invent synchronization 
Do not claim that Employment automatically updates the profile header, Jobs 
recommendations, or other modules without verified product behavior. 
Rule 7 — Do not expose private user data 
A user's Employment history is account-specific data. 
Rule 8 — Use live APIs for account-specific questions 
If the user asks what is actually present on their profile, use an authorized profile 
backend/API. 
Rule 9 — RAG handles general product knowledge 
Use this document for conceptual and navigation questions. 
Rule 10 — Prefer current sources 
The latest authenticated application behavior and approved internal documentation take 
priority over older screenshots or older documents.
